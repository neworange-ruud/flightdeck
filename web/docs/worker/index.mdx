# Quickstart: Worker

A **worker** is FlightDeck running on another machine with no screen of its
own: a spare Mac, a Mac mini under the desk, or a Linux box. The agents, their
worktrees and Git all live there. FlightDeck Desktop on your laptop is the
screen. Close the laptop and the agents keep working. Open it again and you
pick up where they are.

```text
 worker (Mac or Linux, always on)                your computer
 ┌────────────────────────────────┐              ┌──────────────────────────┐
 │ flightdeck worker              │   Tailscale  │ FlightDeck Desktop       │
 │  projects, agents, git, shell  │◄────────────►│  (or flightdeck connect) │
 └────────────────────────────────┘              └──────────────────────────┘
```

Setup takes about 15 minutes, once. After that you only use the Desktop.

## What you need

- **A worker machine** running macOS or Linux (x86_64 or arm64) that stays on.
  Windows can't be a worker.
- **[Tailscale](https://tailscale.com)** on the worker and on your computer,
  signed in to the same tailnet. The worker is only reachable over Tailscale,
  never on your local network or the internet, so there is nothing else to
  secure.
- **FlightDeck Desktop** on your computer. Follow
  [step 1 of the Desktop quickstart](/getting-started#1-install-the-app) if you
  don't have it yet.
- **SSH access to the worker** for the first two steps. After that, the
  Desktop gives you a shell on the worker.

## 1. Install and start the worker

SSH in to the worker and install the `flightdeck` command:

```bash
brew install neworange-ruud/tap/flightdeck
# or, without Homebrew:
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/neworange-ruud/flightdeck/releases/latest/download/flightdeck-installer.sh | sh
```

Then start the worker:

```bash
flightdeck worker start
```

It returns once the worker is running in the background. If it can't start, it
tells you why.

Then make it come back on its own after a reboot:

```bash
flightdeck worker enable
```

This hands the worker to your system's service manager (launchd on a Mac,
systemd on Linux). Your projects and agents resume where they were after every
restart.

<Callout type="note">
  **On a Mac, "on boot" means "at login".** The worker starts when the worker
  account logs in at the screen. For a Mac that reboots unattended, turn on
  automatic login (System Settings → Users & Groups; not available with
  FileVault). If nobody is logged in at the screen yet, `enable` sets it up for
  the next login.

  **On Linux**, `enable` tells you if the account needs *lingering* to start at
  boot instead of at login, and prints the command:
  `sudo loginctl enable-linger $USER`.
</Callout>

## 2. Pair your Desktop

Still on the worker, run:

```bash
flightdeck worker pair
```

```text
Pairing code: 4821   (valid for 120 s, single use)
Address:      box.tail1234.ts.net:7420
```

On your computer, open FlightDeck Desktop, choose **Connect to remote…**, and
enter the address and the code. The code works once and expires after two
minutes; run `flightdeck worker pair` again if it runs out.

![Connect to remote…: the worker's address and the pairing code.](/screenshots/desktop-app/connect-remote.png)

You only pair once. From then on the worker is listed under **WORKERS** in the
launcher, with a status pill and its load, disk space and agent count. Click it
to open the worker's window. You can rename it there to something friendlier
than its hostname.

## 3. Log in to your agents on the worker

The agents run on the worker, so they need to be logged in **there**. The
first tab in the worker's window is the **Worker shell**, a terminal on the
worker. Use it like any terminal:

1. Run each agent CLI you want to use (`claude`, `codex`, `opencode`,
   `cursor-agent`) and finish its login.
2. Make sure Git can push. Run `gh auth login`, or put an SSH key on disk and
   check it with `ssh -T git@github.com`.

![The Worker shell tab: a terminal on the worker for logging in to agents and Git.](/screenshots/desktop-app/worker-shell.png)

FlightDeck never stores or forwards your agent or Git credentials. Agents use
whatever login the worker account has.

<Callout type="warning">
  **macOS workers and Claude Code.** Claude Code keeps its login in the macOS
  Keychain, which an agent started from an SSH session may not be able to read.
  If an agent says it isn't logged in, make sure the worker runs through
  `flightdeck worker enable` with the account logged in at the screen, so it
  runs in that login session. If that doesn't help, put an API key in the
  worker account's shell profile instead (for example `ANTHROPIC_API_KEY`),
  run `flightdeck worker enable` again, then `flightdeck worker restart`.
</Callout>

## 4. Open a project

Choose **Open a project…** in the worker's window. You can:

- pick a repository the worker already has (it looks in `~/flightdeck` by
  default),
- browse the worker's home folder for one, or
- paste a Git URL to **clone** it onto the worker.

![Open a project on the worker: repositories it already has, a folder browser and a clone field.](/screenshots/desktop-app/open-project.png)

## 5. Work as usual

From here it is the same app. Press `Ctrl-n` to start an agent, watch the
sidebar, push from the git strip. Everything on the
[Desktop quickstart](/getting-started#3-start-an-agent) applies.

![A worker's window: the agents run on the worker, the Desktop only shows them.](/screenshots/desktop-app/worker-window.png)

A few things are different on a worker:

- **Closing the window doesn't stop anything.** The agents keep running, and
  the Desktop still sends you a notification when one needs you or finishes.
- **One window at a time.** If you open the worker from a second computer, that
  window takes over and the first one offers **Reconnect**.
- **Mission control and split view** aren't available in a worker's window yet.

## Use a terminal instead of the Desktop

`flightdeck connect` is the terminal UI attached to a worker. It works from any
machine with the `flightdeck` command, over SSH too. Pair once (run
`flightdeck worker pair` on the worker first):

```bash
flightdeck connect --pair box.tail1234.ts.net
```

Then connect whenever you like:

```bash
flightdeck connect
```

![flightdeck connect: the worker's agents in the terminal UI.](/screenshots/tui/connect.png)

The Desktop and `flightdeck connect` share their pairings, so a worker paired in
one shows up in the other. `Ctrl-q` disconnects; the worker keeps running.

## If something looks wrong

| You see | Do this |
| --- | --- |
| **offline** in the WORKERS list | Check Tailscale is up on both machines (`tailscale status`). On the worker, `flightdeck worker status` says whether it runs. |
| "The worker stopped." | Run `flightdeck worker start` on the worker, then **Reconnect**. |
| **version differs** or **update needed** | Update the older side. On the worker: `flightdeck update`, then `flightdeck worker restart`. |
| **Taken over by …** | Another window opened the worker. **Reconnect** takes it back. |
| An agent says it isn't logged in | Log in again in the Worker shell (step 3). |

[Worker in Depth](/worker/operations) covers the security model, logs, crash
recovery, updating, phone pairing and the `[worker]` settings.
