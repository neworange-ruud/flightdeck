# FlightDeck Remote (iOS)

Companion iOS app for FlightDeck — see `specs/MOBILE_REMOTE_PRD.md` at the repo
root for product scope. iOS 18+, iPhone-only in v1, SwiftUI, dark-only
"midnight mission-control" theme.

## Project generation

The `.xcodeproj` is **not committed** — it's generated from `project.yml` via
[XcodeGen](https://github.com/yonaskolb/XcodeGen). Regenerate it any time the
project structure or settings change:

```bash
brew install xcodegen   # one-time, if not already installed
cd ios
xcodegen generate
```

This produces `ios/FlightDeckRemote.xcodeproj`.

## Build

```bash
cd ios
xcodegen generate
xcodebuild build \
  -project FlightDeckRemote.xcodeproj \
  -scheme FlightDeckRemote \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath .derived \
  CODE_SIGNING_ALLOWED=NO
```

## Test

```bash
ios/scripts/test.sh
```

or equivalently:

```bash
cd ios
xcodegen generate
xcodebuild test \
  -project FlightDeckRemote.xcodeproj \
  -scheme FlightDeckRemote \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath .derived \
  -skipPackagePluginValidation \
  CODE_SIGNING_ALLOWED=NO
```

Both the unit test target (`FlightDeckRemoteTests`) and UI test target
(`FlightDeckRemoteUITests`) run as part of the `FlightDeckRemote` scheme.

```
    Features/
      Pairing/                    Pairing flow (stub)
      Projects/                   Projects list (stub)
      Sessions/                   Agent sessions list (stub)
      Chat/                       Agent chat / cleaned transcript (stub)
      Shell/                      Minimal shell terminal (stub)
      Activity/                   Activity feed (stub)
      Settings/                   Settings (stub)
    Resources/
      Assets.xcassets/            AppIcon + AccentColor placeholders
    Info.plist                    Generated by xcodegen from project.yml (not hand-edited)
    PrivacyInfo.xcprivacy         Apple privacy manifest (required for uploads)
    FlightDeckRemote.entitlements          aps-environment: development (Debug)
    FlightDeckRemote-Release.entitlements  aps-environment: production (Release)
  FlightDeckRemoteTests/           Unit tests (Swift Testing)
  FlightDeckRemoteUITests/         UI tests (XCTest / XCUIApplication)
  scripts/test.sh                 xcodegen + xcodebuild test, one command
  scripts/archive.sh              xcodegen + archive + export (+ optional upload)
```

Each `Features/*` folder currently holds a single placeholder view wired up
just enough to compile and be navigable; feature teams fill these in.

## Notable decisions / deviations

- **Swift language mode:** Swift 5 mode (`SWIFT_VERSION: 5.0`), not Swift 6
  strict concurrency. This keeps the scaffold friction-free for feature teams
  starting out; revisit once the Transport layer (actors, `Sendable` models)
  is designed in earnest.
- **SwiftTerm dependency:** added via Swift Package Manager
  (`https://github.com/migueldeicaza/SwiftTerm`, from `1.14.0`), linked to the
  app target but not yet imported/used anywhere — the Shell feature will
  consume it.
- **`.xcodeproj` (and the app target's generated `Info.plist`) are
  gitignored.** `project.yml` is the source of truth for both; run
  `xcodegen generate` after cloning or pulling changes to `project.yml`.
- **Code signing is configured for distribution.** `DEVELOPMENT_TEAM` is
  `7NKCS4AZS9` (DotTech Holding B.V.) with automatic signing; a team id is not
  a secret, so it is committed to keep archives reproducible. Simulator builds
  opt out on the command line (`CODE_SIGNING_ALLOWED=NO`) and need no
  certificate. See **Distribution (TestFlight)** below.
- **`#Preview` bodies are wrapped in `#if DEBUG`.** They reference DEBUG-only
  fixtures (`DebugFixtures.swift`), and the `#Preview` macro expands in Release
  regardless of `ENABLE_PREVIEWS` — so leaving one unguarded breaks the Release
  build (and therefore every archive) while Debug stays green. The `iOS`
  workflow's `release-build` job is what catches this.
- **Dark-only:** `UIUserInterfaceStyle` is forced to `Dark` in the generated
  Info.plist, and the root view also sets `.preferredColorScheme(.dark)`
  in-process.

## Versioning

`CFBundleShortVersionString` in `project.yml` tracks the FlightDeck release
train (`Cargo.toml`'s `version`), and `scripts/release` rewrites both together
so the phone and the desktop never claim different versions. Settings → About
shows `version (build)`.

`CFBundleVersion` is the build number. It must **strictly increase on every
upload** to App Store Connect, independently of the marketing version — reusing
one is rejected. `scripts/release` resets it to `1` when the marketing version
changes; for a second upload of the same version, bump it in `project.yml` or
pass `FD_BUILD_NUMBER=n` to `scripts/archive.sh`.

## Distribution (TestFlight)

```bash
ios/scripts/archive.sh            # archive + export a .ipa
ios/scripts/archive.sh --upload   # ...and send it to App Store Connect
```

Internal TestFlight testing (up to 100 App Store Connect team members) needs
**no App Review** — a build is available to testers minutes after processing.
External testing (public links, up to 10,000 testers) needs Beta App Review,
which brings a real problem with it: the app is inert without a paired Mac
running FlightDeck, so a reviewer cannot exercise it. That will need a demo
path or very good review notes.

The parts that break uploads silently, all now covered by
`FlightDeckRemoteTests/DistributionMetadataTests.swift`:

- **`aps-environment` must match the signing profile.** Debug uses
  `FlightDeckRemote.entitlements` (`development`), Release uses
  `FlightDeckRemote-Release.entitlements` (`production`) — wired per
  configuration in `project.yml`. TestFlight builds are production; a mismatch
  is either a codesign failure or, worse, testers silently never receiving
  notifications.
- **`PrivacyInfo.xcprivacy`** declares the required-reason APIs the app uses
  (`UserDefaults`, CA92.1). A missing or incomplete manifest is rejected at
  upload with ITMS-91053, before any review.
- **`ITSAppUsesNonExemptEncryption: false`** answers export compliance once
  instead of on every upload. All crypto is CryptoKit, which qualifies for the
  OS-provided-encryption exemption — revisit if that ever stops being true.
- **The privacy policy** lives at <https://www.flightdeckai.app/privacy>
  (`web/src/app/privacy/page.tsx`), is linked from Settings → About, and is
  what App Store Connect's privacy-policy field must point at. Keep the page,
  the manifest, and the App Privacy answers in agreement.

First archive on a new machine: automatic signing creates the Apple
Distribution certificate and App Store profile on demand, which requires the
Account Holder or Admin role on the team.
